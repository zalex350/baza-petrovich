# smesitel.by — спецификация обмена с 1С (предварительная)

Версия от 17.11.2026. Полный внутренний документ; короткая спецификация для разработчика 1С — `docs/1C_API_FOR_1C_DEV.md`. Главное: `sku` во всех потоках — код товара на сайте (`LEDEME-L4755-2`), артикул производителя — отдельная колонка `article`; GUID товару присваивает только поток номенклатуры. На тестовом стенде уже работают потоки 1 (номенклатура) и 2 (цены и остатки), в том числе ручная загрузка из админки; потоки 3–6 (заказы, статусы, документы) — формат утверждён, реализация в работе.

**Решения заказчика (13.11.2026):** заказ уходит в 1С только после подтверждения менеджером сайта (раздел 6); ручная смена статуса на сайте разрешена, статус из 1С применяется, если он новее (раздел 7); счёт PDF из 1С — поток 6 (раздел 7); склад один; дробные количества (до 3 знаков) для части товаров (разделы 4–6); персональные цены клиентов будут, формат — после ответа 1С (вопрос 10.3).

**Изменения с версии 13.11.2026:**
- раздел 5: типы цен — колонки `price_<код>` (правила 10–11); **цены передаются без НДС** (решение заказчика 17.11.2026, правило 9), примеры — без НДС.

**Изменения с версии 12.11.2026:**
- раздел 3, 4: карта кодов `GET /catalog/sku-map` — CSV «guid;sku» товаров с GUID;
- раздел 4: минимальное количество и кратность (`min_qty`, `qty_step`) в обмен не входят — ведутся только в админке сайта, такие колонки в файле игнорируются; допустимые ставки НДС; `mode=full` не скрывает товары, которых нет в файле, а отдаёт их список; правило 7 (`hidden_by_1c`) — `active = 1` не показывает товар, скрытый вручную, и как работает кнопка «Показать / Скрыть»; правило 11 — ошибки и предупреждения строки с точными текстами, длина полей; ручная загрузка и раздел «Новые из 1С»;
- раздел 5: тексты ошибок строк; строка с пустым `guid` ищется по `sku`;
- раздел 6: правило количества (кратность);
- раздел 8: точный состав ответа `GET /jobs/{id}` с примером номенклатуры; ключи `summary`; `missing` и `unmatched` — до 1000 записей с признаком `*_truncated`;
- раздел 3, 7: поток 6 — документы по заказу (`POST /orders/{номер}/documents`); частоты потоков — как в короткой спецификации;
- раздел 4–6: один склад; дробные количества до 3 знаков (решение, реализация на сайте в работе);
- раздел 6: в `/orders/new` — только заказы, подтверждённые менеджером (статус «Подтверждён»);
- раздел 7: ручная смена статуса на сайте и правило «статус 1С применяется, если новее»;
- раздел 10: все открытые вопросы — к заказчику (технические он передаёт своему разработчику 1С); ответы заказчика отмечены «Решено».

## 1. Назначение и принципы

1С сама обращается к сайту по HTTPS: отправляет файлы с номенклатурой, ценами, остатками, статусами и документами по заказам и забирает новые заказы. Сайт принимает файл, сохраняет его в архив, обрабатывает в очереди и отдаёт результат по каждой строке.

Документ предварительный: форматы и поля уточняются вместе с разработчиком 1С (раздел 10).

| Данные | Владелец | Что делает обмен |
| --- | --- | --- |
| Артикул, наименование 1С, производитель, единица измерения, ставка НДС | 1С | Сайт обновляет из 1С |
| Цена, остаток | 1С | Сайт обновляет из 1С |
| Код товара на сайте (SKU, `LEDEME-L4755-2`) | Сайт | Сайт присваивает новым товарам и возвращает 1С; 1С передаёт его в `sku` во всех потоках |
| Отображаемое название, описание, фото, документы товара, характеристики, категория, SEO, минимальное количество и кратность заказа | Сайт | Обмен не трогает |
| Заказ | Сайт до регистрации, 1С после | Менеджер сайта подтверждает, сайт отдаёт, 1С подтверждает запись и присылает статусы; менеджер может менять статус вручную |
| Счёт на оплату (PDF) | 1С | 1С присылает по заказу, сайт показывает клиенту в кабинете |

Ключ сопоставления — GUID 1С. Код сайта (`sku`) и «бренд + артикул» используются только при первичном сопоставлении, пока у товаров на сайте нет GUID.

## 2. Транспорт и безопасность

Все запросы — HTTPS (TLS 1.2+), токен в заголовке и доступ только с IP-адресов 1С.

| Параметр | Значение |
| --- | --- |
| Базовый адрес, тестовый стенд | `https://test.smesitel.by/api/1c/v1` |
| Базовый адрес, рабочий сайт | `https://smesitel.by/api/1c/v1` (после запуска) |
| Авторизация | Заголовок `Authorization: Bearer <токен>`. Токен выдаётся отдельно для стенда и для рабочего сайта, передаётся не по почте |
| Ограничение по IP | Только внешние IP 1С из списка (вопрос 10.5) |
| Кодировка | UTF-8 (BOM допускается). Десятичный разделитель — точка, без разделителей тысяч |
| Файлы | Тело запроса = сам файл (`Content-Type: text/csv` или `application/json`); можно сжать (`Content-Encoding: gzip`). До 50 МБ |
| Повторная отправка | Заголовок `X-Exchange-Id` — уникальный идентификатор пакета (GUID: латиница, цифры, дефис, до 64 символов). Повтор с тем же id не читается и не обрабатывается заново, а возвращает прежнее задание (202, текущий статус). Тот же id для другого потока — 409 `exchange_id_conflict` |
| Частота | До 60 запросов в минуту на токен (настройка сайта); сверх — 429 с `Retry-After` |
| Время в ответах | ISO 8601 по Минску: `2026-11-10T18:30:00+03:00` (Europe/Minsk) |
| Время в запросах | ISO 8601 с любым смещением: `+03:00`, `Z`, `+00:00` — сайт пересчитывает сам. Без смещения — время по Минску. Не ISO 8601 — ошибка строки |
| CORS | Не поддерживается: заголовков `Access-Control-Allow-*` нет, API вызывается сервером 1С, а не браузером |
| Проверка связи | `GET /ping` → `{"status": "ok", "server_time": …, "token": "<название токена>", "ip": "<адрес, который видит сайт>"}` |
| Версия | `v1` в адресе; несовместимые изменения — только в `v2` |

**Коды ответа**

| Код | Значение | Что делать 1С |
| --- | --- | --- |
| 200 | Готово (чтение, подтверждение) | — |
| 202 | Файл принят в обработку, в ответе `job_id` | При необходимости проверить результат (раздел 8) |
| 400 | Файл не читается: нет заголовка, неверная кодировка, нет обязательных колонок (коды ниже) | Исправить файл, не повторять как есть |
| 401 / 403 | Неверный токен / IP не в списке | Проверить настройки |
| 404 | Нет такого заказа / задания | — |
| 409 | Конфликт: например, заказ уже подтверждён с другим GUID | Разобраться вручную |
| 413 | Файл больше 50 МБ | Сжать или разбить |
| 429 | Слишком часто | Повторить через `Retry-After` секунд |
| 500 / 503 | Сбой сайта | Повторить с тем же `X-Exchange-Id` через 1, 5, 15 минут |

Ошибки возвращаются в теле ответа: `{"error": "код", "message": "текст на русском"}`.

| Код `error` | HTTP | Когда |
| --- | --- | --- |
| `unauthorized` | 401 | Нет заголовка `Authorization: Bearer`, токен неверный или отозван |
| `ip_forbidden` | 403 | IP не в белом списке (проверяется раньше токена; пустой список — запрещено всё) |
| `unsupported_content_type` | 400 | `Content-Type` не тот, что ожидает адрес (`text/csv` для потоков 1–2) |
| `unsupported_encoding` | 400 | `Content-Encoding` не `gzip` |
| `bad_gzip` | 400 | `Content-Encoding: gzip`, но тело не gzip или архив повреждён |
| `empty_body` | 400 | Пустое тело или пустой файл |
| `bad_encoding` | 400 | Не UTF-8 |
| `missing_columns` | 400 | В первой строке CSV нет обязательных колонок (в `message` — какие) |
| `bad_json` | 400 | Тело не JSON (потоки 4–5) |
| `bad_mode` | 400 | `mode` не `full` / `delta` |
| `bad_exchange_id` | 400 | `X-Exchange-Id` не в формате GUID |
| `not_found` | 404 | Нет задания / заказа / адреса |
| `exchange_id_conflict` | 409 | `X-Exchange-Id` уже использован другим потоком |
| `payload_too_large` | 413 | Больше 50 МБ — и сжатое тело, и распакованное |
| `too_many_requests` | 429 | Сверх частоты, ждать `Retry-After` секунд |
| `server_error` | 500 | Сбой сайта — повторить с тем же `X-Exchange-Id` |

## 3. Потоки обмена

Шесть потоков, все запускает 1С по расписанию или по событию. Сайт сам в 1С не обращается.

| # | Поток | Запрос | Формат | Частота (предложение) |
| --- | --- | --- | --- | --- |
| 1 | Номенклатура 1С → сайт | `POST /catalog` | CSV | Полная — раз в сутки (ночью), изменения — по событию или раз в час |
| 2 | Цены и остатки 1С → сайт | `POST /prices-stock` | CSV | Изменения — каждые 15–30 минут, полная — раз в сутки |
| 3 | Новые заказы сайт → 1С | `GET /orders/new` | JSON | Каждые 5 минут |
| 4 | Подтверждение заказа 1С → сайт | `POST /orders/{номер}/confirm` или `/reject` | JSON | Сразу после записи заказа в 1С |
| 5 | Статусы заказов 1С → сайт | `POST /order-statuses` | JSON | По изменению статуса или каждые 15 минут |
| 6 | Документы по заказу (счёт PDF) 1С → сайт | `POST /orders/{номер}/documents` | multipart/form-data | После выставления счёта |
| — | Результат обработки файла | `GET /jobs/{job_id}` | JSON | По необходимости |
| — | Карта кодов «GUID → код сайта» | `GET /catalog/sku-map` | CSV | После загрузки номенклатуры или для сверки (раздел 4) |

Порядок важен: номенклатура раньше цен и остатков. Строка цен с неизвестным GUID уходит в ошибки задания и не создаёт товар.

## 4. Поток 1 — номенклатура

`POST /catalog?mode=full|delta[&dry_run=1]`, тело — CSV, разделитель `;`, первая строка — заголовок. Ответ 202 с `job_id`.

| Колонка | Обяз. | Описание |
| --- | --- | --- |
| `guid` | да | GUID номенклатуры в 1С |
| `sku` | нет | **Код товара на сайте (SKU)**: `LEDEME-L4755-2` — то же значение, что в потоках 2 и 3. Пусто — у новой позиции 1С кода сайта ещё нет: сайт сопоставит её по «бренд + артикул» или создаст товар и вернёт код (правила 1–3). Колонки может не быть, если в 1С нет поля под код сайта (вопрос 10.12) |
| `article` | да | Артикул производителя **без бренда**: `L4755-2` |
| `brand` | нет | Производитель / бренд. Нужен для сопоставления и создания товара без `sku` (правила 1–2) |
| `name` | да | Наименование в 1С, до 255 символов (длиннее — обрезается с предупреждением) |
| `unit` | да | Единица измерения: `шт`, `м`, `компл` …, до 20 символов. Колонка обязательна, пустое значение — `шт` |
| `vat_rate` | да | Ставка НДС: только `20`, `10`, `0` или `без НДС`. Регистр и пробелы не важны; `20%`, `20 %`, `20.00` принимаются как `20`. Пусто или любое другое значение (`15`, `18%`, `НДС 20`) — ошибка строки (правило 11) |
| `barcode` | нет | Штрихкод |
| `group_1c` | нет | Группа в 1С — только для справки (подсказывает контент-менеджеру категорию для новых товаров), на категорию сайта не влияет |
| `active` | да | `1` — продаётся, `0` — выведен / помечен на удаление (принимаются и `true` / `false`) |

Минимальное количество заказа и кратность (упаковка) в обмен не входят: их ведёт админка сайта (правило количества — раздел 6). Колонки `min_qty`, `qty_step`, как и любые другие лишние колонки, игнорируются без проверки; новый товар получает значения по умолчанию сайта — 1 и 1.

**Количества.** Склад один: остаток — общий по товару. Решение заказчика: для части товаров (метры, килограммы и т. п.) количества дробные — до 3 знаков после точки (`12.5`), для штучных — целые. Реализация на сайте в работе (признак дробности товара, остаток, корзина, заказ); до неё остаток и количество в заказе — только целые, дробный остаток — ошибка строки потока 2.

```csv
guid;sku;article;brand;name;unit;vat_rate;barcode;group_1c;active
5f1c2b8a-3d4e-11ef-9a1b-0050569a1c01;LEDEME-L4755-2;L4755-2;LEDEME;Смеситель для кухни LEDEME L4755-2;шт;20;4810000000017;Смесители;1
6a2d3c9b-3d4e-11ef-9a1b-0050569a1c02;TUBOFLEX-FLX-050-12;FLX-050-12;TUBOFLEX;Подводка гибкая 1/2 50 см;шт;20;;Подводка;1
8c4f5e1d-3d4e-11ef-9a1b-0050569a1c04;;BL 5810;TIM;Смеситель для ванны TIM BL5810;шт;20;;Смесители;1
7b3e4d0c-3d4e-11ef-9a1b-0050569a1c03;SAVOL-OLD-001;OLD-001;SAVOL;Выведенный товар;шт;20;;Аксессуары;0
```

Третья строка — новая позиция 1С без кода сайта: сайт найдёт её по «бренд + артикул» (`TIM` + `BL5810`) или создаст товар `TIM-BL 5810`.

**Правила обработки**

1. Поиск товара на сайте:
   1. по `guid` (без учёта регистра);
   2. не найден, `sku` заполнен — по точному совпадению `sku` с кодом товара на сайте, как в потоке 2 (раздел 5, правило 1): без учёта регистра и пробелов по краям, внутренние пробелы значимы; только среди товаров без GUID. Товар с таким кодом есть, но с другим GUID, или кода на сайте нет — ошибка строки, товар не меняется и не создаётся: заполненный `sku` — ссылка на существующий товар сайта;
   3. `sku` пуст — по ключу «бренд + артикул», только среди товаров без GUID. Нормализация `brand` и `article`: без учёта регистра; пробелы схлопываются в один и обрезаются по краям; кириллические буквы-двойники латиницы (А, В, Е, К, М, Н, О, Р, С, Т, Х) считаются латинскими; «—» и «–» — дефисом. **Дефисы значимы**: `L4755-2` и `L47552` — разные артикулы. Пример: `Ledeme` + `l  4755–2` → `LEDEME` + `L 4755-2`; `LEDEME` + `L2237-В` (кириллическая «В») → `LEDEME` + `L2237-B`. Несколько совпадений — ошибка строки «неоднозначное сопоставление», товар не меняется и не создаётся. Без `brand` — ошибка строки: по одному артикулу товары разных брендов не сопоставляются.

   Найден по `sku` или по ключу — сайт запоминает GUID. **GUID товару присваивает только этот поток.** Код сайта у найденного товара обмен не меняет; если `sku` строки отличается от кода товара, найденного по GUID, — предупреждение задания, строка применяется.
2. `sku` пуст и по ключу не найден — создаётся новый товар **черновиком**: не опубликован, без категории, без цены, остаток 0, минимальное количество и кратность — 1. Он попадает в раздел админки «Товары → Новые из 1С»; на сайте появится после того, как контент-менеджер назначит категорию и опубликует. Если в строке `active = 0`, товар после публикации остаётся скрытым как выведенный в 1С. Код сайта — `БРЕНД-артикул`: `brand` в верхнем регистре, `article` как есть, пробелы по краям убраны (`Tim` + `BL 5810` → `TIM-BL 5810`). Код уникален без учёта регистра и пробелов по краям; занят — добавляется суффикс `-2`, `-3` … (`TIM-BL 5810-2`) и предупреждение задания «код TIM-BL 5810 занят, присвоен TIM-BL 5810-2».
3. Созданные коды сайт возвращает в результате задания (`GET /jobs/{id}`, поле `created`), чтобы 1С сохранила их у себя и дальше передавала в `sku` (раздел 8):

   Пример для третьей строки CSV выше, если код `TIM-BL 5810` на сайте уже занят:

   ```json
   "created": [{"line": 4, "guid": "8c4f5e1d-3d4e-11ef-9a1b-0050569a1c04", "sku": "TIM-BL 5810-2"}],
   "warnings": [{"line": 4, "guid": "8c4f5e1d-3d4e-11ef-9a1b-0050569a1c04", "sku": "TIM-BL 5810-2", "message": "Код TIM-BL 5810 занят, присвоен TIM-BL 5810-2"}]
   ```

   `created` отдаётся целиком, без ограничения в 1000 строк, как у `errors`. При `dry_run=1` в `created` — коды, которые были бы присвоены; товары не создаются.
4. Обновляются только поля из таблицы, кроме `sku`: `name` (наименование 1С), артикул, бренд, единица, НДС, штрихкод, группа 1С, `active` (правило 7); сайт отмечает время обмена у каждой применённой строки, даже без изменений. Набор полей 1С — настройка сайта `SHOP_1C_MANAGED_FIELDS` (по умолчанию `article, name, brand, unit, vat_rate, price, stock`; цена и остаток — поток 2); штрихкод и группа 1С пишутся всегда. Код сайта, отображаемое название, описание, фото, категория, характеристики, документы и SEO не меняются.
5. Покупатель видит отображаемое название сайта, а если оно не задано — `name` из 1С. Перед запуском обмена текущие названия сайта перенесены в отображаемое название, поэтому первая выгрузка не меняет названия на витрине.
6. У товаров с GUID поля из таблицы в админке только для чтения: их владелец — 1С. Исключение — `sku`: код сайта принадлежит сайту, но у товара с GUID его лучше не менять — 1С хранит код у себя, и после смены в потоках 2 и 3 будет другое значение (сопоставление при этом идёт по GUID и не ломается).
7. Видимость (`active`) и отметка «выведен в 1С» (`hidden_by_1c`):
   - `active = 0`, товар показан — товар скрывается с витрины с отметкой «выведен в 1С», данные сайта сохраняются (`summary.hidden`);
   - `active = 0`, товар уже скрыт на сайте вручную — ничего не меняется, отметка не ставится;
   - `active = 1` снова показывает только товар с отметкой «выведен в 1С» (`summary.shown`); товар, скрытый на сайте вручную, остаётся скрытым — решение администратора сайта важнее;
   - кнопка «Показать / Скрыть» в админке снимает отметку. Поэтому товар, который администратор показал вручную, снова скроет следующая строка с `active = 0`, а скрытый вручную не покажет строка с `active = 1`;
   - новый товар из строки с `active = 0` создаётся скрытым с отметкой; после публикации в «Новых из 1С» он остаётся скрытым, пока не придёт `active = 1`.
8. `mode=full`: товары с GUID, которых нет в файле, не скрываются и не удаляются: сайт отдаёт их список (`missing` в результате задания), решение принимает администратор. Выведенный товар 1С передаёт строкой с `active = 0`. `mode=delta` (по умолчанию): меняются только товары из файла.
9. Предохранитель `mode=full`: если в файле нет больше **10 %** товаров сайта с GUID (порог — в настройках сайта), задание завершается `failed`, данные сайта не меняются. Так неполный файл не ломает каталог. `message`: «mode=full: в файле нет 120 из 1000 товаров с GUID (12 % при пороге 10 %) — файл похож на неполный, данные сайта не изменены». В пробном прогоне (`dry_run=1`) задание не падает: причина — в `summary.guard` и в `message` («… предохранитель mode=full сработал бы: … — без dry_run задание завершится failed»).
10. `dry_run=1` — пробный прогон: сайт сопоставляет строки и отдаёт отчёт в результате задания (сопоставлено по GUID / по `sku` / по ключу, будет создано с кодами, изменится — по каждому полю, будет скрыто / показано, неоднозначные, ошибки и предупреждения, товары сайта без пары — `unmatched`), данные не меняются. Результат пробного прогона совпадает с тем, что даст реальная загрузка того же файла. Используется при первичном сопоставлении (раздел 9).
11. Ошибки строки (`errors`): строка не применяется, товар не меняется и не создаётся; остальные строки применяются. Несколько ошибок одной строки — одной записью через «; ». Тексты (`message`):

    | Случай | Текст |
    | --- | --- |
    | Пустые обязательные значения | «Нет GUID», «Нет наименования (name)», «Нет артикула (article)», «Нет ставки НДС (vat_rate)», «Нет признака active» |
    | Длина: `guid` > 64, `sku` / `article` / `brand` > 255, `unit` > 20, `barcode` > 64 | «Поле unit длиннее 20 символов» |
    | Ставка НДС не из списка | «Ставка НДС «15»: допустимо 20, 10, 0 или «без НДС»» |
    | `active` не `1` / `0` | «active «да»: ожидается 1 или 0» |
    | `guid` повторяется в файле | «GUID повторяется в файле (строка 12)» |
    | Две строки с разными GUID нашли один товар сайта | «Товар сайта LEDEME-L4755-2 уже сопоставлен строке 12» |
    | Заполненный `sku` (правило 1.2) | «Товар с SKU «…» на сайте не найден: заполненный sku — код существующего товара сайта; у новой позиции оставьте sku пустым»; «SKU «…» — у товара сайта с другим GUID»; «SKU «…» есть у нескольких товаров сайта без GUID» |
    | Пустой `sku` без бренда (правило 1.3) | «Нет бренда (brand): без sku товар сопоставляется и создаётся по «бренд + артикул»» |
    | Артикул пуст после нормализации | «Артикул «…» не годится для сопоставления» |
    | Неоднозначное сопоставление | «Неоднозначное сопоставление: «LEDEME» + «L4755-2» — у товаров сайта LEDEME-L4755-2, LEDEME-L4755-2A; укажите sku нужного товара» |
    | Код нового товара с суффиксом длиннее 255 | «Код сайта «…» длиннее 255 символов» |

    Предупреждения (`warnings`) — строка применена:

    | Случай | Текст |
    | --- | --- |
    | `name` или `group_1c` длиннее 255 — обрезается | «Поле name длиннее 255 символов — обрезано» |
    | `sku` строки не совпадает с кодом товара, найденного по GUID | «SKU «…» отличается от кода товара на сайте «…» (товар найден по GUID, код сайта не меняется)» |
    | Код нового товара занят (правило 2) | «Код TIM-BL 5810 занят, присвоен TIM-BL 5810-2» |

    В записи ошибки `guid` и `sku` — значения из строки файла (пустые — `null`); в предупреждении `sku` — код товара на сайте (найденного или созданного). В журнале `guid` хранится до 64 символов, `sku` — до 255, `message` — до 2000: длиннее — обрезается.

**Ручная загрузка.** Файл номенклатуры того же формата можно загрузить в админке сайта («Обмен с 1С» → «Загрузить номенклатуру»): CSV (разделитель «;», UTF-8 или Windows-1251) или .xlsx (первый лист), режим `delta` / `full`, шаблон .xlsx. Если срабатывает предохранитель `mode=full` (правило 9), «Применить» недоступно. Предпросмотр считает то же, что пробный прогон: привязка GUID к товарам сайта (по `sku` или по бренду и артикулу), изменения «было → стало», создаваемые товары с кодами, ошибки и предупреждения; список товаров сайта без пары — в режиме `full`. База меняется только после «Применить»; задание попадает в журнал с источником «вручную» и автором. Главный сценарий — первичная привязка GUID по выгрузке из 1С до подключения API.

**Карта кодов.** `GET /catalog/sku-map` — коды сайта всех товаров с GUID, чтобы 1С сверила или заполнила у себя поле под код сайта (вопрос 10.12) — например, после первичного сопоставления, когда GUID присвоены товарам, найденным по `sku` или по «бренд + артикул». Доступ — как у всего API (IP + токен, раздел 2).

- Ответ 200, `Content-Type: text/csv; charset=UTF-8`, UTF-8 без BOM, разделитель `;`, строки через `\n`, первая строка — заголовок `guid;sku`.
- Все не удалённые товары с GUID, в том числе черновики («Новые из 1С») и скрытые; без GUID и удалённые — нет. Порядок — по `sku`.
- Значение с `;`, кавычкой или переводом строки — в кавычках, кавычки удваиваются (`"AQUA;1"`).
- `Accept-Encoding: gzip` — ответ сжат (`Content-Encoding: gzip`); без заголовка — обычный.
- Товаров с GUID нет — только заголовок.

```csv
guid;sku
5f1c2b8a-3d4e-11ef-9a1b-0050569a1c01;LEDEME-L4755-2
8c4f5e1d-3d4e-11ef-9a1b-0050569a1c04;TIM-BL 5810-2
```

## 5. Поток 2 — цены и остатки

`POST /prices-stock?mode=full|delta`, тело — CSV, разделитель `;`, первая строка — заголовок; порядок колонок любой, лишние колонки игнорируются. Ответ 202 с `job_id`.

| Колонка | Обяз. | Описание |
| --- | --- | --- |
| `guid` | да | GUID номенклатуры (без учёта регистра) |
| `sku` | да | **Код товара на сайте (SKU)**, например `LEDEME-L4755-2`, — не артикул производителя. Пока у товара на сайте нет GUID — для поиска (правило 1); в ошибках — для читаемости |
| `price_<код>` | нет | Цена **типа цены** `<код>` (справочник «Типы цен» сайта: `opt` «Оптовая» — по умолчанию, `retail`, `special`, `vip`), BYN, до 2 знаков: `832.26`. **Без НДС** — сайт записывает цену как есть, НДС добавляет по ставке товара (правило 9). Колонки — те же цены, что в 1С, без НДС. Колонок сколько угодно, по одной на тип. Пусто — у товара нет цены этого типа (у типа по умолчанию — «Цена уточняется», заказать нельзя); **колонки нет в файле — цена этого типа не меняется** |
| `price` | нет | Прежняя колонка — то же, что `price_opt` (совместимость). Есть обе — берётся `price_opt` |
| `stock` | да | Свободный остаток (за вычетом резервов 1С) в единицах `unit`, ≥ 0; склад один. Сейчас — целое число; для дробных единиц будет до 3 знаков (`12.5`, раздел 4, «Количества») |
| `stock_status` | нет | `in_stock` / `on_order` / `none` — если товар возится под заказ при нулевом остатке. `on_order` — на сайте «Под заказ», `in_stock` / `none` — снимает признак; **колонки нет или значение пустое — «Под заказ» не меняется** |
| `updated_at` | да | Момент снятия данных в 1С, ISO 8601 с любым смещением (раздел 2) |

```csv
guid;sku;price_opt;price_retail;price_vip;stock;stock_status;updated_at
5f1c2b8a-3d4e-11ef-9a1b-0050569a1c01;LEDEME-L4755-2;832.26;915.48;790.64;7;in_stock;2026-11-10T18:30:00+03:00
6a2d3c9b-3d4e-11ef-9a1b-0050569a1c02;TUBOFLEX-FLX-050-12;4.20;4.62;;350;in_stock;2026-11-10T18:30:00+03:00
8c4f5e1d-3d4e-11ef-9a1b-0050569a1c04;TIM-BL5800;;;;0;on_order;2026-11-10T18:30:00+03:00
```

Во второй строке у товара нет VIP-цены: клиент с типом VIP увидит оптовую (цену по умолчанию). Цены — без НДС: на сайте `832.26` без НДС, при ставке товара 20 % покупатель видит и `998.71` с НДС.

**Правила обработки**

1. Товар ищется по `guid` (без учёта регистра). Не найден — по точному совпадению `sku` с кодом товара на сайте: без учёта регистра и пробелов по краям, внутренние пробелы значимы (`TIM-AM-GVS 15-04` и `TIM-AM-GVS15-04` — разные товары). Подходят только товары без GUID: товар с другим GUID — другая позиция 1С, строка уходит в ошибки. Несколько совпадений (SKU отличаются только регистром) — ошибка строки. Поиск по артикулу производителя выключен (настройка сайта `SHOP_1C_MATCH_BY_ARTICLE`; при включении — только среди товаров без GUID, неоднозначность — ошибка). **GUID товару присваивает только поток 1 (номенклатура)**; поток цен его не присваивает. Не найден — ошибка строки, товар не создаётся. Колонка `guid` обязательна, но значение может быть пустым — тогда товар ищется только по `sku`; пусты оба — ошибка «Нет GUID и SKU».
2. `mode=delta` (каждые 15 минут): в файле только товары, у которых изменились цена или остаток.
3. `mode=full` (раз в сутки): все активные товары. У товаров с GUID, которых нет в файле, остаток становится 0 (время остатка — самое позднее `updated_at` файла), цена не меняется; сколько обнулено — в `message` задания. Предохранитель — как в разделе 4, правило 9: нет больше 10 % товаров с GUID — `failed`, ничего не меняется. **Строка с ошибкой тоже считается «товар в файле»: остаток такого товара не обнуляется** (строка просто не применяется).
4. Строка со старым `updated_at` (раньше уже применённого для этого товара — отдельно для цены и для остатка) пропускается (`rows_skipped`) — защита от повтора старого файла. Тот же момент — применяется заново. Если в файле товар повторяется, действует строка с самым поздним `updated_at`.
5. Ошибки строк (`errors` задания, номер строки — как в файле, считая заголовок; все ошибки строки — одной записью через «; »). Строка с ошибкой не применяется, остальные — применяются.

   | Случай | Текст |
   | --- | --- |
   | Товар не найден | «Товар с таким GUID не найден»; «Товар с таким GUID не найден, SKU «…» — у товара с другим GUID»; «Товар с таким GUID не найден, SKU «…» есть у нескольких товаров сайта»; «Товар с SKU «…» не найден» (пустой `guid`); «Нет GUID и SKU» |
   | Цена | «Цена «12,50»: ожидается точка»; «Цена «-5»: отрицательная»; «Цена «…»: ожидается число до 2 знаков после точки, без пробелов»; для `price_<код>` — «Цена price_retail «…»: …» |
   | Остаток | «Нет остатка»; «Остаток «-1»: отрицательный»; «Остаток «…»: ожидается целое число ≥ 0» |
   | `stock_status` | «Признак наличия «…»: ожидается in_stock, on_order или none» |
   | `updated_at` | «Дата «…»: ожидается ISO 8601, например 2026-11-10T18:30:00+03:00» |
6. Сайт хранит остаток 1С как есть и сам его при оформлении заказа не списывает. Покупатель видит **доступный остаток** = остаток 1С минус резерв сайта.
7. Резерв сайта — количество в заказах, которые 1С ещё не учла в остатке:
   - заказ ждёт передачи в 1С (поток 4 ещё не пришёл) или отклонён 1С (`/reject`) и ждёт решения менеджера;
   - заказ подтверждён, но последний применённый остаток снят раньше подтверждения (`updated_at` остатка < `registered_at` заказа). Резерв снимается, когда приходит остаток с `updated_at ≥ registered_at`, — так между подтверждением и следующей выгрузкой товар не продаётся дважды.

   Отменённые заказы в резерв не входят. Отклонённый заказ менеджер либо отменяет (резерв снимается), либо отправляет в 1С повторно (заказ снова попадает в `/orders/new`).
8. У покупателей цена и наличие в корзине перепроверяются перед оформлением, изменения показываются покупателю.
9. **Цены и НДС.** Цены в файле — **без НДС** (решение заказчика 17.11.2026): сайт записывает их как есть, хранит цены без НДС и считает НДС от них по ставке товара (`vat_rate` из потока 1; у нового товара — 20 %) — на витрине «с НДС», в заказе построчно. Если когда-нибудь 1С начнёт присылать цены с НДС — на сайте включается настройка «Цены из 1С с НДС» («Обмен с 1С» → «Настройки», по умолчанию выключена): тогда цена без НДС = цена с НДС / (1 + ставка товара), округление до копеек (`998.71` при 20 % → `832.26`; «Без НДС» и 0 % — та же цена).
10. **Типы цен.** Код типа — латиница, цифры, `_`, `-`, до 30 знаков; регистр в заголовке не важен. Колонка с **неизвестным кодом** создаёт тип автоматически — **скрытым** (клиентам не применяется, пока администратор не снимет «Скрытый» в «Типы цен»), — и предупреждение в задании (`warnings`): «Колонка «price_…»: типа цены «…» нет — он создаётся скрытым…». Неверный код (`price_опт`, `price_`) — предупреждение, колонка не читается. Цена типа по умолчанию дублируется в общую цену товара. Отметка времени цены (правило 4) — одна на товар для всех типов; строка без колонок цен время цены не меняет.
11. **Какая цена у клиента.** Организации на сайте назначается «Применяемая цена» (тип или «по умолчанию»). Витрина, поиск, сортировка и фильтр по цене, корзина, заказ и выгрузки клиенту — по цене этого типа; нет её у товара — цена по умолчанию; нет и её — «Цена уточняется». Название типа клиент не видит. Позже возможен тип цены по категориям товара — формат файла от этого не изменится.

**Ручная загрузка.** Тот же файл можно загрузить в админке сайта («Обмен с 1С» → «Загрузить цены»): CSV (разделитель «;», UTF-8 или Windows-1251) или .xlsx (первый лист; дата Excel — ячейка-дата или её серийный номер, например `46336.77`, — без пояса, время по Минску), режим `delta` / `full`. Сначала предпросмотр — будет обновлено (цена каждого типа без НДС «было → стало», остаток, «под заказ»), без изменений, устаревшие, ошибки по строкам, предупреждения (новые типы цен), что обнулится в `full`; база меняется только после «Применить». Правила те же, что для файла от 1С, задание попадает в общий журнал с источником «вручную» и автором (в `GET /jobs/{id}` — `"source": "manual"`, у файлов 1С — `"api"`). Шаблон .xlsx — там же: колонка `price_<код>` на каждый тип справочника.

Склад один — остаток общий по товару, по складам не передаётся (вопрос 10.4, решено). Персональные цены — через типы цен (вопрос 10.3, решено): 1С передаёт цену каждого типа своей колонкой `price_<код>`, тип клиенту назначается на сайте.

## 6. Потоки 3 и 4 — заказы и их подтверждение

Менеджер сайта проверяет и подтверждает новый заказ; 1С забирает подтверждённые заказы, записывает их у себя и подтверждает каждый. Пока заказ не подтверждён, сайт отдаёт его в каждом следующем запросе, поэтому потеря ответа не теряет заказ.

У заказа два независимых признака: **статус** (видит покупатель, раздел 7) и **состояние обмена** — «ожидает передачи в 1С» / «передан» / «отклонён» (видит менеджер в админке). Отдельного статуса «Ожидает передачи в 1С» нет.

**3. `GET /orders/new?limit=50`** — заказы в состоянии «ожидает передачи», старые первыми: статус «Подтверждён» (менеджер сайта проверил заказ), нет `guid_1c`, не отклонён. Заказы в статусе «Новый» (ещё не проверены) и отменённые до передачи не отдаются.

```json
    "number": "SM-2026-000024",

    "organization": {"guid": "c1d2e3f4-...", "unp": "193123457", "name": "ООО «Рога и копыта»"},
    "user": {"name": "Иван Петров", "email": "buyer@example.by", "phone": "+375290000000"},
    "delivery_address": {"guid": null, "title": "Склад №2", "address": "г. Минск, ул. Примерная, 1"},
    "comment": "Позвонить за час до доставки",
    "currency": "BYN",
    "total_without_vat": 931.26, "vat": 186.25, "total": 1117.51,
    "items": [{
      "product_guid": "5f1c2b8a-3d4e-11ef-9a1b-0050569a1c01",
      "sku": "LEDEME-L4755-2", "article": "L4755-2", "client_code": "WB-001",
      "name": "Смеситель для кухни LEDEME L4755-2",
      "qty": 1, "unit": "шт", "price": 832.26, "vat_rate": 20,
      "sum": 832.26, "vat": 166.45, "total": 998.71
    }]
  }]
}
```

- `price` — цена без НДС на момент оформления; суммы округлены до копеек по строке.
- `sku` — код товара на сайте (как в потоках 1 и 2), `article` — артикул производителя без бренда (`null`, если не заполнен), `product_guid` — GUID номенклатуры 1С (`null`, если товар ещё не сопоставлен). `product_guid`, `sku`, `article`, `name`, `unit` — снимок на момент оформления, не зависят от последующих изменений товара.
- `qty` — кратно кратности товара и не меньше минимального заказа (сайт округляет вверх при добавлении в корзину). Сейчас целое; для товаров с дробной единицей будет до 3 знаков (раздел 4, «Количества»).
- `vat_rate` — `20`, `10`, `0` или `null` для «без НДС».
- `client_code` — код товара у клиента (маркетплейса), `null`, если нет.
- `organization.guid` — GUID контрагента 1С, если он заполнен на сайте; иначе 1С ищет по УНП (вопрос 10.6).

**4. Подтверждение.** `POST /orders/SM-2026-000024/confirm`

```json
{"guid_1c": "a9b8c7d6-...", "number_1c": "ЗК-000512", "registered_at": "2026-11-10T18:47:03+03:00"}
```

Сайт сохраняет номер, GUID и время регистрации в 1С, ставит статус «Передан в 1С» и состояние обмена «передан» и больше не отдаёт заказ.

| Ситуация | Ответ |
| --- | --- |
| Подтверждение принято | 200 |
| Повторное подтверждение с тем же `guid_1c` | 200, ничего не меняется |
| Заказ уже подтверждён с другим `guid_1c` | 409 `{"error": "guid_conflict"}` |
| Заказ отменён на сайте, пока 1С его записывала | 409 `{"error": "order_cancelled"}` — 1С отменяет у себя записанный документ |
| Нет такого заказа | 404 |

**Отказ.** `POST /orders/SM-2026-000024/reject` с `{"reason": "Контрагент не найден по УНП"}` — состояние обмена «отклонён» с причиной, заказ уходит менеджеру сайта на разбор и в `/orders/new` не попадает, пока менеджер не отправит его повторно; в журнале обмена — ошибка. Статус для покупателя не меняется.

Порядок для покупателя (решение заказчика, SRS BR-173/174): заказ на сайте создаётся со статусом «Новый»; менеджер проверяет его и подтверждает — «Подтверждён», с этого момента 1С забирает его в `/orders/new`; после подтверждения 1С (поток 4) — «Передан в 1С». Резерв сайта действует с оформления, в том числе пока заказ ждёт проверки менеджером (раздел 5, правило 7).

## 7. Потоки 5 и 6 — статусы и документы заказов

**5. Статусы.**

`POST /order-statuses`, тело — JSON-массив изменений. Ответ 200 с результатом по каждому заказу.

```json
{"statuses": [
  {"number": "SM-2026-000024", "guid_1c": "a9b8c7d6-...", "status": "shipped",
   "changed_at": "2026-11-11T10:15:00+03:00", "comment": "ТТН № 0123456"}
]}
```

| Код `status` | Статус на сайте |
| --- | --- |
| `in_work` | В работе (сборка) |
| `shipped` | Отгружен |
| `completed` | Выполнен |
| `cancelled` | Отменён (причина — в `comment`) |

Кода `confirmed` в потоке 5 нет: о регистрации заказа в 1С сообщает подтверждение (поток 4), после него статус на сайте — «Передан в 1С». «Подтверждён» на сайте — шаг до передачи: заказ проверен менеджером и ждёт 1С (раздел 6).

- Статус принимается только для заказа, переданного в 1С (есть `guid_1c`).
- Статусы идут только вперёд: «Передан в 1С» → «В работе» → «Отгружен» → «Выполнен»; промежуточные можно пропускать (например, сразу `shipped`). Возврат назад — ошибка по этому заказу, остальные применяются.
- `cancelled` принимается из любого незавершённого статуса.
- Статус с `changed_at` старше уже применённого игнорируется (`ignored`).
- Ручная смена статуса на сайте разрешена (решение заказчика): менеджер меняет статус в админке, смена попадает в историю с пометкой «вручную» и со временем изменения. Статус из 1С применяется, если его `changed_at` новее последней смены статуса на сайте — ручной или из 1С; более старый — `ignored`. Порядок «только вперёд» проверяется среди статусов из 1С; поверх ручного статуса более новый статус 1С применяется всегда (например, менеджер вручную поставил «Отгружен», 1С позже присылает `in_work` — на сайте «В работе»): данные учётной системы новее.
- Каждый статус попадает в историю заказа с пометкой «1С»; покупатель видит его в кабинете.
- Отмена по запросу клиента остаётся на сайте: менеджер одобряет её и отменяет заказ в 1С; 1С присылает `cancelled`.
- По SRS (BR-175) статусы меняются по данным 1С; ручная смена на сайте — дополнительно (правило выше).

Результат по каждому заказу: `{"number": "SM-2026-000024", "result": "ok" | "ignored" | "error", "message": "…"}` (`ignored` — устаревший `changed_at` или такой статус уже стоит).

**6. Документы.** `POST /orders/SM-2026-000024/documents`, `Content-Type: multipart/form-data` — документ по заказу из 1С, сейчас — счёт на оплату (SRS §8.10).

| Поле | Обяз. | Описание |
| --- | --- | --- |
| `file` | да | PDF, до 10 МБ |
| `type` | да | `invoice` — счёт на оплату; позже — `waybill` (ТТН), `act` |
| `number` | да | Номер документа в 1С |
| `date` | да | Дата документа, ISO 8601 (`2026-11-13` или со временем) |
| `guid_1c` | да | GUID документа в 1С |

- Заказ ищется по номеру сайта; нет — 404. Принимается для заказа, переданного в 1С (есть `guid_1c` заказа).
- Ответ 200. Счёт появляется в кабинете клиента в карточке заказа (кнопка «Счёт»), в админке — с пометкой «из 1С».
- У заказа один счёт: новый заменяет прежний — и присланный 1С, и загруженный менеджером вручную. Повтор с тем же `guid_1c` заменяет файл.
- На сайте счёт хранится как сейчас при ручной загрузке (`OrderInvoice`, источник `erp`, `external_id` = `guid_1c` документа); файл — закрытый, отдаётся только владельцу заказа и менеджеру.
- Ошибки: не PDF или больше 10 МБ — 400 / 413; неизвестный `type` — 400. Коды `error` — при реализации, в общем формате раздела 2.

## 8. Задания и журнал обмена

Каждый принятый файл становится заданием. Ошибка в одной строке не останавливает остальные (BR-178), данные сайта при ошибке не повреждаются (BR-177).

Ответ на отправку файла, 202:

```json
{"job_id": "0193f2a1-7c5e-7a10-9b2d-3e4f5a6b7c8d", "status": "queued"}
```

Файл проверяется до постановки в очередь (кодировка, заголовок CSV — коды 400 выше); строки — уже в задании.

`GET /jobs/{job_id}` — результат. Поля во всех заданиях:

| Поле | Значение |
| --- | --- |
| `job_id`, `type` | Идентификатор; поток: `catalog`, `prices-stock` … |
| `source` | `api` — файл от 1С, `manual` — загружен в админке |
| `status` | `queued` / `processing` / `done` / `failed` (ниже) |
| `received_at`, `finished_at` | Время по Минску (раздел 2); пока задание не завершено — `finished_at: null` |
| `rows_total`, `rows_ok`, `rows_skipped`, `rows_error` | Строк в файле (без заголовка), применено, пропущено (устаревший `updated_at`, поток 2), с ошибкой |
| `message` | Итог одной строкой или причина `failed`; может быть `null` |
| `errors`, `errors_truncated` | Ошибки строк `{"line", "guid", "sku", "message"}` — до 1000; больше — `errors_truncated: true`, полный список — в журнале обмена на сайте |
| `warnings`, `warnings_truncated` | Предупреждения (строка применена), тот же формат и то же ограничение |

Пример — цены и остатки:

```json
{
  "job_id": "0193f2a1-...", "type": "prices-stock", "source": "api", "status": "done",
  "received_at": "2026-11-10T18:30:05+03:00", "finished_at": "2026-11-10T18:30:21+03:00",
  "rows_total": 11227, "rows_ok": 11224, "rows_skipped": 1, "rows_error": 2,
  "message": "mode=full: остаток 0 у 3 товаров с GUID, которых нет в файле",
  "errors": [
    {"line": 418, "guid": "8c4f5e1d-...", "sku": "TIM-BL5800", "message": "Товар с таким GUID не найден"},
    {"line": 902, "guid": "9d5a6f2e-...", "sku": "SAVOL-S-01", "message": "Цена «12,50»: ожидается точка"}
  ],
  "errors_truncated": false,
  "warnings": [], "warnings_truncated": false
}
```

У номенклатуры (`type: catalog`) ещё:

| Поле | Значение |
| --- | --- |
| `dry_run` | `true` — пробный прогон, данные не менялись (раздел 4, правило 10) |
| `summary` | Счётчики (таблица ниже); пока задание не обработано и у `failed` — `{}` |
| `created` | Созданные товары `{"line", "guid", "sku"}` — целиком, без ограничения (раздел 4, правило 3); в пробном прогоне — коды, которые были бы присвоены |
| `missing`, `missing_truncated` | `mode=full`: товары сайта с GUID, которых нет в файле, `{"guid", "sku"}` — до 1000 (раздел 4, правило 8) |
| `unmatched`, `unmatched_truncated` | Пробный прогон: товары сайта (не удалённые) без пары в файле, `{"guid", "sku"}` (`guid` — `null`, если ещё не присвоен) — до 1000 (раздел 4, правило 10) |

Ключи `summary`:

| Ключ | Значение |
| --- | --- |
| `matched_by_guid`, `matched_by_sku`, `matched_by_key` | Строк сопоставлено по GUID / по `sku` / по «бренд + артикул» (по `sku` и ключу — GUID присвоен) |
| `created` | Создано товаров (черновиков) |
| `updated`, `unchanged` | Найденных товаров, у которых что-то изменилось / ничего не изменилось (обновилось только время обмена) |
| `fields` | Поле → у скольких товаров изменится: `name`, `article`, `brand`, `unit`, `vat_rate`, `barcode`, `group_1c`, `guid` (присвоен), `is_active` (скрыт или показан); только изменившиеся поля, по алфавиту |
| `hidden`, `shown` | Скрыто по `active = 0` / снова показано по `active = 1` (раздел 4, правило 7) |
| `errors`, `warnings` | Всего ошибок и предупреждений (без ограничения в 1000) |
| `missing`, `unmatched` | Всего записей в `missing` / `unmatched` |
| `guard` | Только в пробном прогоне, если сработал бы предохранитель `mode=full`: причина (раздел 4, правило 9) |

Пример — номенклатура, файл из раздела 4 (`mode=delta`): первая строка найдена по GUID без изменений, вторая — по `sku` (GUID присвоен), третья создана с суффиксом, в четвёртой вместо ставки `20` — `18%`:

```json
{
  "job_id": "0193f2b7-...", "type": "catalog", "source": "api", "status": "done",
  "received_at": "2026-11-13T02:00:04+03:00", "finished_at": "2026-11-13T02:00:09+03:00",
  "rows_total": 4, "rows_ok": 3, "rows_skipped": 0, "rows_error": 1,
  "message": "Сопоставлено по GUID 1, по SKU 1, по бренду и артикулу 0; создано 1; изменено 1, без изменений 1; скрыто 0, показано 0",
  "errors": [
    {"line": 5, "guid": "7b3e4d0c-3d4e-11ef-9a1b-0050569a1c03", "sku": "SAVOL-OLD-001", "message": "Ставка НДС «18%»: допустимо 20, 10, 0 или «без НДС»"}
  ],
  "errors_truncated": false,
  "dry_run": false,
  "summary": {
    "matched_by_guid": 1, "matched_by_sku": 1, "matched_by_key": 0,
    "created": 1, "updated": 1, "unchanged": 1,
    "fields": {"guid": 1},
    "hidden": 0, "shown": 0,
    "errors": 1, "warnings": 1, "missing": 0, "unmatched": 0
  },
  "created": [{"line": 4, "guid": "8c4f5e1d-3d4e-11ef-9a1b-0050569a1c04", "sku": "TIM-BL 5810-2"}],
  "warnings": [{"line": 4, "guid": "8c4f5e1d-3d4e-11ef-9a1b-0050569a1c04", "sku": "TIM-BL 5810-2", "message": "Код TIM-BL 5810 занят, присвоен TIM-BL 5810-2"}],
  "warnings_truncated": false,
  "missing": [], "missing_truncated": false,
  "unmatched": [], "unmatched_truncated": false

```

Пробный прогон дописывает в начало `message` «Пробный прогон, данные сайта не изменены.»; `mode=full` с товарами вне файла — «mode=full: N товаров с GUID нет в файле — не скрыты, список в отчёте задания».

| `status` | Значение |
| --- | --- |
| `queued` | Ждёт обработки |
| `processing` | Обрабатывается |
| `done` | Готово, возможны ошибки по отдельным строкам |
| `failed` | Файл не обработан целиком, данные сайта не изменились; причина — в поле `message` |

В админке сайта задание `done` с ошибками строк показывается как «Готово с ошибками»; в API статус остаётся `done`.

На стороне сайта:

- архив всех принятых файлов (распакованных) — 90 дней, затем файл удаляется, запись журнала остаётся;
- журнал обмена в админке: дата, тип, операция (импорт / экспорт), счётчики, ошибки по строкам, скачивание исходного файла (SRS §11.12);
- письмо администратору, если: задание `failed`, ошибок больше 5%, цены и остатки не приходили больше 2 часов или заказ не подтверждён 1С дольше 30 минут. Пороги и частота писем (не чаще раза в час на вид) — в настройках обмена в админке. Письмо «цены и остатки не приходили» — только после первой успешной загрузки цен (от 1С или вручную); письмо о заказах включается после подключения выгрузки заказов.

## 9. Порядок запуска

Запуск — на тестовом стенде, затем тот же порядок на рабочем сайте.

| Шаг | Кто | Что |
| --- | --- | --- |
| 0 | Сайт | Подготовка данных: артикулы без бренда и ключ «бренд + артикул» заполнены из каталога, названия сайта перенесены в отображаемое название, добавлены поля номенклатуры 1С |
| 1 | Заказчик + 1С | Ответы на вопросы раздела 10, пробная выгрузка 100–200 строк номенклатуры и цен файлом |
| 2 | Сайт | Финализация спецификации и реализация API на стенде; выдача токена |
| 3 | 1С + сайт | Первичное сопоставление пробным прогоном: полная номенклатура с `mode=delta&dry_run=1` (или выгрузка из 1С файлом — предпросмотр ручной загрузки в админке). Отчёт: сопоставлено / неоднозначные / новые / товары сайта без пары; данные не меняются |
| 4 | Заказчик | Разбор отчёта: исправить артикулы и бренды в 1С или на сайте. Отдельно — товары сайта без бренда (около 390): без бренда по ключу они не сопоставятся |
| 5 | 1С + сайт | Боевая полная номенклатура (`mode=delta`, через API или ручной загрузкой): сайт присваивает GUID и создаёт черновики новых товаров («Новые из 1С»); 1С сохраняет у себя коды сайта из `created` или из карты кодов `GET /catalog/sku-map` (если есть поле под SKU — вопрос 10.12) |
| 6 | 1С | Регулярные цены и остатки по расписанию |
| 7 | 1С + сайт | Заказы: тестовый заказ на сайте → менеджер подтверждает → 1С забирает → подтверждение → статусы и счёт |
| 8 | Все | Неделя параллельной работы на стенде, затем перенос на рабочий сайт |

До запуска обмена цены и остатки можно загружать тем же CSV из админки вручную.

## 10. Открытые вопросы к заказчику

Все вопросы задаются заказчику; технические (1–12) он передаёт своему разработчику 1С вместе с короткой спецификацией `docs/1C_API_FOR_1C_DEV.md`. Номера сохранены — на них ссылаются разделы выше.

**Учёт в 1С (через разработчика 1С)**

1. Какая конфигурация и версия 1С (УТ 11, УНФ, КА, нетиповая)? Есть ли ограничения на исходящие HTTPS-запросы?
2. Что лежит в реквизите «Артикул»: артикул производителя (`L4755-2`) или свой код? Он идёт в колонку `article`; сопоставление позиций без кода сайта — по «бренд + артикул» без учёта регистра, лишних пробелов и кириллицы вместо латиницы; дефисы значимы (раздел 4, правило 1). Как в 1С записаны бренды (нужен список написаний: `TIM` / `TIM Thermo`, `Ledeme` / `LEDEME`)? У всех ли позиций заполнен производитель?
3. Цены: одна оптовая для всех или есть типы цен / персональные цены и скидки контрагентов? Есть ли рекомендованная розничная цена? — **Решено:** типы цен — `opt` «Оптовая» (по умолчанию), `retail` «Розничная», `special` «Специальная», `vip` «VIP»; 1С передаёт их колонками `price_<код>` без НДС (раздел 5), тип клиенту назначается на сайте. Открыто: коды типов в 1С совпадают с этими или нужен другой список (новый код создаст тип на сайте скрытым).
4. Остатки: один склад или несколько? Отдаём сумму или по складам? — **Решено: склад один.** Открыто: Подтвердите, что `stock` — свободный остаток за вычетом резервов 1С, включая заказы сайта, уже записанные в 1С: на этом построен резерв сайта (раздел 5, правило 7). Есть ли признак «под заказ»?
5. С каких внешних IP 1С будет обращаться к сайту?
6. Контрагенты: есть ли GUID и можно ли выгрузить список «УНП — GUID», чтобы заполнить их на сайте? Нужны ли договор и адрес доставки из 1С в заказе?
7. Каким документом заказ записывается в 1С (Заказ клиента)? Сразу проводится или проверяется менеджером? (На сайте решено: в 1С уходит только заказ, подтверждённый менеджером сайта, — раздел 6.) Может ли 1С отменить записанный документ, если сайт ответил `409 order_cancelled`?
8. Какие статусы заказа есть в 1С и как они соотносятся с таблицей раздела 7 (`in_work`, `shipped`, `completed`, `cancelled`)?
9. Может ли 1С отдавать счёт на оплату PDF по заказу (для кабинета клиента, SRS §8.10)? — **Решено:** поток 6 (раздел 7).
10. Какая частота выгрузки цен и остатков реальна без нагрузки на 1С? Резерв сайта держится до прихода остатка, снятого после регистрации заказа (раздел 5, правило 7): чем реже выгрузка, тем дольше количество заказа не возвращается в доступный остаток.
11. Есть ли товары с дробными количествами (метры, килограммы)? — **Решено:** да, для части товаров, до 3 знаков (раздел 4, «Количества»). Открыто: по какому признаку в 1С отличать такие товары (единица измерения или реквизит).
12. Есть ли в 1С поле под код товара на сайте (SKU, `LEDEME-L4755-2`), или его можно завести (дополнительный реквизит номенклатуры)? Если да — 1С передаёт его в `sku` во всех потоках и сохраняет коды новых товаров из `created` (раздел 4, правило 3). Если нет — номенклатура идёт по `guid` + «бренд + артикул» без колонки `sku`, а в ценах и остатках товар находится по `guid`: GUID присваивается при первой выгрузке номенклатуры, поэтому она должна прийти раньше цен (раздел 3).

**Порядок работы**

13. Заказ уходит в 1С сразу или после проверки менеджером на сайте? — **Решено:** только после подтверждения менеджером (раздел 6).
14. Ручная смена статуса на сайте остаётся или только по данным 1С? — **Решено:** остаётся; статус из 1С применяется, если новее (раздел 7). Поверх ручного статуса более новый статус 1С применяется, даже если он «назад» по цепочке.

Решено также: минимальное количество заказа и кратность ведёт только сайт (админка), из 1С не передаются (раздел 4).
