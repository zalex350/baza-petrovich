# Модули smesitel.by

По каждому модулю: назначение, маршруты, код, ключевые правила и тесты. Общая картина — `docs/ARCHITECTURE.md`, полная карта «URL → шаблон» — `docs/UI_INVENTORY.md`.

Пути шаблонов даны от `resources/views/`, тесты — от `tests/Feature/`. Номера BR-… и SRS §… — из ТЗ заказчика, они же стоят в комментариях кода.

Один порядок — мегаменю, мобильное меню, `/catalog`, плитки главной, чипы и плитки подкатегорий (всё из дерева `CatalogMenu`) и список в админке. Тесты — `CatalogSortingTest` |
| Подборки | «Акции» (`is_promo`), «Новинки» (`is_new`), «Хиты» (`is_hit`) — тот же список (`CatalogListing` без категории, с флагом): фильтры по умолчанию, сортировка, вид, «Показать ещё» |

## 2. Поиск

**Назначение.** Поиск по товарам с учётом форм слов и синонимов, живые подсказки в шапке.

| | |
|---|---|
| Маршруты | `GET /search?q=`, `GET /search/suggest?q=` (JSON); админка — `GET/POST /admin/search-synonyms`, `POST /admin/search-synonym/{id}`, `…/delete` |
| Контроллер | `SearchController` (`index`, `suggest`), `Admin\AdminSearchSynonymController` |
| Сервисы | `App\Services\Search`: `SearchText` (нормализация, стемминг Snowball — `wamania/php-stemmer`), `SearchIndex` (`products.search_text`), `SearchSynonyms` (правила из БД, кэш), `ProductSearch` (условия и порядок) |
| Таблицы | `products.search_text`, `search_synonyms` (`terms`, `targets` — пусто у группы) |
| Команда | `php artisan search:reindex` — пересчитать индекс всех товаров (после смены правил нормализации или правок в БД мимо модели) |
| Шаблоны | `search`, `x-product-row` |
| JS | `search-suggest.js` (шапка), `skuSuggest` (корзина, тот же `/search/suggest`) |

Ключевые правила:

| Правило | Суть |
|---|---|
| Индекс | `products.search_text` — « слово основа … »: слова (нижний регистр, «ё» → «е», без служебных «для», «с», «в»…) и их основы (русские — стеммером: «смесители» → «смесител») из названия сайта, наименования 1С, бренда, категории с родителями. Пересчёт: сохранение товара (`Product::booted`), переименование / перенос категории (`Category::booted`, с подкатегориями), обмен с 1С (`CatalogHandler::write` — изменённые название / бренд), импорт каталога (весь индекс), `search:reindex` |
| Поиск | Запрос — по словам, нужны все (порядок не важен). Слово находится: по основе целым словом или началом слова индекса (`SearchToken::sql`: «смеси» → «смеситель», «ванна» → «ванны», но не «вантуз»); по синониму; подстрокой — в `article`, `sku`, коде своей организации, на странице результатов — и в `description`. Только служебные слова — ничего |
| Синонимы | Админка «Синонимы поиска»: строка «смеситель, кран» — группа (в обе стороны), «мойка → раковина» (или `->`) — по левым словам ищутся ещё и правые. Слово может быть фразой («вентиль, шаровой кран»); формы слов не важны (нормализуются, как запрос). Кэш `SearchSynonyms::CACHE_KEY` сбрасывает модель при сохранении / удалении — без деплоя. Стартовые 15 правил — `SearchSynonymSeeder` из миграции, только в пустую таблицу. «Проверить запрос» (`?check=`) — во что развернулся запрос, сколько нашлось на витрине (как у гостя), первые 10, время |
| Порядок | Точный код организации → точный артикул или sku → все слова в названии как есть → все слова по основам → остальные (синонимы, артикул / описание подстрокой); внутри — по названию. По 24 на страницу |
| «Возможно, вы искали» | Ничего не найдено — `ArticleSearch::didYouMean`: до 3 артикулов, совпадающих без учёта дефисов и пробелов (`L47552` → «Возможно, вы искали L4755-2», ссылка на поиск); на странице поиска и в подсказках шапки (`did_you_mean`). Только подсказка, без перехода |
| Артикул на витрине | «Арт. …» — `Product::displayArticle()` (артикул производителя, без него — sku): строка товара, плитка, карточка (с «копировать»), корзина, подсказки (`article`, `brand`; sku в JSON не отдаётся). SKU — внутренний код обмена с 1С, покупателям не показывается |
| Подсказки | От 2 символов: до 5 товаров (без описания) и до 5 категорий — по тем же основам и синонимам, по названию с родителями, выводится путь («Смесители / Для кухни»), верхние уровни первыми |
| Скорость | 11 тыс. товаров, MySQL: SQL поиска 15–36 мс, подсказка целиком (HTTP) — 105–140 мс; `LIKE` по `search_text` без FULLTEXT |
| Видимость | Только `is_active` и `is_published` |
| Тесты | SQLite не приводит кириллицу к нижнему регистру — в тестах «название как есть» латиница (индекс `search_text` в нижнем регистре — кириллица работает) |

Тесты: `SearchTest`, `Search/SearchMorphologyTest`, `Search/AdminSearchSynonymTest`.

## 4. Корзина и CartValidator

**Назначение.** Корзина клиента в БД; проверка позиций перед показом и оформлением.

| | |
|---|---|
| Маршруты (auth) | `GET /order`; `POST /order/add/{id}`, `/order/update/{id}`, `/order/delete/{id}`, `/order/select/{id}`, `/order/select-all`, `/order/clear`, `/order/quick-add`, `/order/accept-prices` |
| Контроллер | `CartController` |
| Сервисы | `CartValidator` → `CartValidationResult` (+ `CartProblem`), `CartSummary` (сводка для шапки и строк списков), `Vat\VatCalculator` |
| Модели | `Cart` (одна на пользователя), `CartItem` (`price_at_add`, `selected`, `product_name`) |
| Enum | `CartState` (Пустая / Требует корректировки / Требует обновления / Готова), `CartProblemType` (коды ERR-013…ERR-018) |
| Шаблоны | `order` (корзина и оформление), `x-cart-row`, `x-cart-quick-add`, `x-qty` |
| JS | `cart-page.js`, `cart-actions.js`, `qty-sync.js`, `skuSuggest` |

Ключевые правила:

| Правило | Суть |
|---|---|
| BR-121 | Корзина только у клиента; администратору вместо «В корзину» — переход к товару в админке |
| BR-099 | Корзина не резервирует остаток |
| BR-101 | Валидатор возвращает **все** проблемы всех позиций сразу, а не первую |
| BR-123…BR-125 | Проверки позиции: товар существует, активен, опубликован, есть цена, кратность (`min_qty`, `qty_step`), остаток, цена не изменилась с `price_at_add`. Правило количества — `App\Support\OrderQuantity` (одно для каталога, карточки, корзины, «Добавить по артикулу», повтора и оформления; в `x-qty` — та же формула): кратно `qty_step` и не меньше `min_qty`, первое допустимое — `ceil(min_qty / qty_step) × qty_step` (мин. 2, кратность 3 → 3, 6, 9). Ввод округляется вверх с подсказкой «Округлено до 6 — кратно 3»; «−» не ниже первого допустимого. В админке `min_qty`, не кратный шагу, сохраняется с подсказкой «будет округлено до N»; `default_qty` — только допустимое |
| Состояние | Изменение цены — «Требует обновления», пользователь принимает новые цены кнопкой (`accept-prices`); остальное — «Требует корректировки», пользователь исправляет сам |
| Добавление | Проверяется итоговое количество (уже в корзине + добавляемое); строка корзины блокируется, параллельные добавления не дублируют позицию |
| Строка списка и карточка | «В корзину» видна всегда: товар уже в корзине — количество добавляется к имеющемуся; под количеством «В корзине: N шт. · перейти» (место оставлено во всех строках). Колонки строки фиксированной ширины — токены `grid-cols-product-row`, `grid-cols-product-buy` |
| Шапка | Счётчик и сумма с НДС — по одним и тем же позициям (все доступные с ценой), галочка «в заказ» на них не влияет; отмеченные считаются только в панели «Ваш заказ» |
| «Добавить по артикулу» | Артикул + количество (пусто — `default_qty`); ошибки у полей. Поиск: `product_id` (выбор из подсказки) → код организации → артикул или sku (`ArticleSearch::whereExact`, без регистра и пробелов по краям). Артикул у нескольких товаров — ничего не добавляется, выбор «БРЕНД · Арт. … — название» (`x-cart-quick-choices`: JSON — `choices_html`, без JS — сессия `CartController::QUICK_CHOICES`); не найден — «Возможно, вы искали …» без добавления |
| Выбор | В заказ идут только позиции с галочкой (`selected`); добавленная позиция отмечается автоматически |
| Ответы | При `Accept: application/json` — JSON со сводкой для шапки, иначе редирект назад |

Тесты: `CartValidatorTest`, `CartQuantityRuleTest`, `CartSelectionTest`, `CartOrderSplitTest`, `CartOrderSplitMigrationTest`, `Storefront/ListAddToCartTest`.

## 5. Оформление и CheckoutService

**Назначение.** Создание заказа из отмеченных позиций корзины в одной транзакции.

| | |
|---|---|
| Маршруты (auth) | `POST /order/checkout` (форма на странице корзины; `GET /order/checkout` → редирект в `/order`), `GET /order/{id}/placed` |
| Контроллеры | `CartController::checkout`, `OrderController::placed` |
| Сервисы | `CheckoutService::place`, `CartValidator`, `OrderStatusService::recordPlaced`, `Vat\VatCalculator` |
| Модели | `Order`, `OrderItem`, `DeliveryAddress`, `Product` |
| Исключение | `CheckoutException` (пустая корзина, ничего не выбрано, нет адреса, чужой адрес, перечень проблем) |
| Событие | `OrderPlaced` → письма администраторам |
| Шаблоны | `order`, `order_placed`, `partials/vat_totals`, `partials/order_delivery` |

Ключевые правила:

| Правило | Суть |
|---|---|
| BR-121 | Оформляет только клиент, только на свою организацию |
| BR-123, BR-124, BR-134 | Транзакция: блокировка корзины и товаров (в порядке id), повторная проверка, резерв остатка (`StockReserve`: доступный = остаток 1С − заказы, не учтённые 1С; остаток 1С не списывается), снимок позиций (в том числе `product_guid`, `unit`), удаление оформленных позиций; неотмеченные остаются |
| BR-135 | Любая проблема отменяет оформление с полным перечнем причин |
| BR-128, BR-129 | Адрес доставки обязателен и должен принадлежать организации; в заказ копируется снимком |
| BR-132 | Номер `SM-ГГГГ-000001`, сквозной в пределах года (`order_sequences`, атомарный upsert) |
| Повтор формы | Одноразовый `checkout_token`: повторная отправка возвращает уже созданный заказ |
| НДС | Снимок по позициям: цена без НДС × количество, НДС по позиции с округлением до копеек, итог — сумма позиций; `vat_rate = null` — «Без НДС» |
| Комментарий | Необязателен, пустой сохраняется как `null` |

Тесты: `CheckoutValidationTest`, `CheckoutDeliveryTest`, `CheckoutOrganizationTest`, `OrderVatTest`, `Unit/MoneyTest`.

## 6. Заказы и статусы

**Назначение.** Жизненный цикл заказа, история, запрос клиента на отмену.

| | |
|---|---|
| Сервис | `OrderStatusService` (`change`, `requestCancel`, `approveCancel`, `rejectCancel`, `recordPlaced`) |
| Модели | `Order`, `OrderItem`, `OrderStatusHistory` (только добавляется) |
| Enum | `OrderStatus` (переходы, цвета), `OrderHistoryEvent` (запрос отмены, отказ) |
| Исключения | `InvalidStatusTransition`, `CancelRequestException` |
| Событие | `CancelRequested` → письма администраторам |
| Шаблоны | `partials/order_items`, `partials/order_history`, `partials/order_status`, `partials/cancel_request_badge` |

Переходы статусов (`OrderStatus::allowedTransitions`):

| Из | В |
|---|---|
| Новый | Подтверждён, Отменён |
| Подтверждён | Передан в 1С, Отменён |
| Передан в 1С | В работе |
| В работе | Отгружен |
| Отгружен | Выполнен |
| Выполнен, Отменён | — (финальные) |

Ключевые правила:

| Правило | Суть |

### 8.3. Категории и фильтры каталога

«Категории» (`/admin/categories`, `AdminCategoryController`): дерево в порядке витрины (`Catalog\CategoryOrder`, раздел 1 «Порядок категорий»); сверху — переключатель «Порядок категорий» (`POST /admin/categories/order-mode`: по количеству товаров / только вручную / по алфавиту); колонка «Товаров» — опубликованных с подкатегориями (по ним порядок; в подсказке — всего в самой категории). «↑ / ↓»: по количеству — закрепляют категорию и соседей выше её нового места (`is_pinned`, пометка «закреплена», «Вернуть автопорядок» — `POST /admin/category/{id}/unpin`, и в списке, и в карточке категории); вручную — перенумеровывают `sort_order`; по алфавиту — не показываются. `Category::ordered()` (`sort_order`, название) — для служебных списков (фильтры каталога, выбор родителя). Создать (с родителем; адрес — из названия, занят — `-2`), переименовать (slug сохраняется — старые ссылки работают), переместить (смена родителя — в конец соседей, вместе с подкатегориями и товарами; в себя и в свою подкатегорию нельзя), «↑ / ↓», картинка — webp (`Images\WebpImage`, 600 px) для плиток подкатегорий, скрыть / показать (`is_hidden`: нет в меню и каталоге вместе с подкатегориями, товары — в поиске), удалить — только пустую (иначе ошибка «товаров — N, подкатегорий — M»). | Режимы | «Добавить и обновить» (по умолчанию) — остальные коды клиента не меняются; «Заменить полностью» — коды товаров, которых нет в файле, удаляются |
| Предпросмотр | Добавить / обновить (было → стало) / удалить (режим «Заменить») / без изменений / ошибки по строкам: пустое поле, артикул не найден, артикул у нескольких товаров (перечень «БРЕНД · Арт.»), бренд не совпал, код длиннее 100, код или товар повторяется в файле (ошибка у всех таких строк), код занят товаром, код которого файл не меняет. База не меняется |
| Применение | В транзакции, с повторной проверкой по текущей базе. Строки с ошибками пропускаются; в режиме «Заменить» при ошибках применить нельзя (иначе удалились бы коды товаров из ошибочных строк). Обмен кодами между товарами в одном файле работает (сначала удаление, потом вставка). После — отчёт на вкладке: добавлено, обновлено, удалено, без изменений, пропущенные строки |
| Уникальность | Один код на товар у организации `(organization_id, product_id)`; код не повторяется у организации `(organization_id, code)` |
| Удаление | Каскадно вместе с товаром или организацией |
| Регистр | В MySQL `(organization_id, code)` не различает регистр, в SQLite различает — при импорте и в формах сравнивать без учёта регистра. Поиск по коду — по `code_key` (не `LOWER(code)`: SQLite не приводит кириллицу к нижнему регистру) — одинаково в обеих базах |
| Кто видит | Только пользователь организации и только её коды. Гость, администратор, пользователь без организации — ни кодов, ни запросов к ним |
| «Ваш код» | Под артикулом: строка товара (`x-product-row`), плитка (`x-product-card`), карточка товара (с «копировать»), позиция корзины (`x-cart-row`). Нет кода — только наш артикул. Коды страницы загружают контроллеры (`CatalogController`, `HomeController`, `SearchController`, `ProductController`, `CartController::index`) — `ClientCodes::load` |
| Поиск | `/search` и `/search/suggest` (раздел 2): каждое слово запроса — по основам и синонимам в названии, бренде, категории, подстрокой — в артикуле (описании) или в коде своей организации; точное совпадение с кодом — первым, затем с артикулом. Подсказка в шапке — «Ваш код X · артикул · название»; в JSON подсказок — `client_code` |
| Корзина | Если у организации есть коды — полоса «Добавить по вашему коду» (`x-cart-quick-add by-code`): подсказки «ваш код · артикул», выбор подставляет код; `quickAdd` ищет сначала код организации, затем артикул. Иначе — «Добавить по артикулу» |
| Заказ | `CheckoutService` пишет в позицию `client_code` — код на момент оформления (позже не меняется). Показ: заказ в кабинете («Ваш код»), админка заказа («Код клиента») — `partials/order_items`; письмо о новом заказе — список позиций «артикул (код клиента: X) — название × N шт.» |
| Выгрузка ассортимента | Кабинет → «Выгрузка ассортимента» (`/account/assortment`, пункт меню — только у организации с кодами, иначе 404). Файл `.xlsx` (`App\Services\AssortmentExport`, openspout, потоково): ваш код, артикул (`displayArticle`; SKU не выводится), бренд, название, цена без НДС, цена с НДС (по ставке товара; нет цены — «Цена уточняется»), остаток — точным числом до `shop.export_stock_cap` (20, `SHOP_EXPORT_STOCK_CAP`), больше — «более 20». Товары — опубликованные (`is_active`, `is_published`) с кодом своей организации, по артикулу; галочка «Включить товары без кода» — после них все остальные опубликованные с пустым кодом. Код и артикул — текстом (ведущие нули сохраняются) |

Тесты: `ProductClientCodeTest`, `ClientCodesAdminTest`.

## 12. Обмен с 1С: API и журнал

**Назначение.** 1С обращается к сайту по HTTPS (`/api/1c/v1`, `docs/1C_EXCHANGE_SPEC.md`): присылает файлы номенклатуры, цен и остатков, статусов, забирает заказы. Этап 2 — транспорт, задания, журнал и оповещения; этап 3 — цены и остатки (`PricesStockHandler`); этап 4 — номенклатура (`CatalogHandler`); заказы — этап 5 (пока заглушка: задание сразу `done`, 0 строк).

| | |
|---|---|
| Маршруты API | `routes/api.php`: `GET /ping`, `POST /catalog`, `GET /catalog/sku-map`, `POST /prices-stock` (`?mode=full\|delta`), `GET /jobs/{id}` — `Api\ExchangeController` |
| Карта кодов | `GET /catalog/sku-map` — `SkuMap::csv()`: CSV «guid;sku» (UTF-8 без BOM, `\n`) по не удалённым товарам с GUID (и черновикам, и скрытым), по sku; ячейки с «;» / кавычкой — в кавычках. `Accept-Encoding: gzip` (не `q=0`) — сжатый ответ, `Vary: Accept-Encoding`.
