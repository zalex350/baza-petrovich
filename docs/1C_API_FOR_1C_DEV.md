# smesitel.by — обмен с 1С (API для разработчика 1С)

Версия 13.11.2026. 1С сама обращается к сайту по HTTPS: отправляет номенклатуру, цены, остатки и статусы, забирает заказы. Сайт в 1С не обращается.

Ключ товара — **GUID номенклатуры 1С**. Кроме него 1С хранит у себя **код товара на сайте (SKU)**, например `LEDEME-L4755-2`, в дополнительном реквизите номенклатуры и передаёт его в потоках 1 и 2.

## 1. Транспорт

| Параметр | Значение |
| --- | --- |
| Адрес (тестовый стенд) | `https://test.smesitel.by/api/1c/v1` |
| Авторизация | `Authorization: Bearer <токен>` (токен передаётся отдельно) |
| Доступ | Только с IP 1С из белого списка сайта |
| Формат | CSV (`;`, UTF-8, первая строка — заголовок) для потоков 1–2; JSON для 3–5. Десятичный разделитель — точка |
| Сжатие | По желанию: `Content-Encoding: gzip`. До 50 МБ |
| Повтор пакета | Заголовок `X-Exchange-Id` (уникальный id пакета, до 64 символов). Повтор с тем же id не обрабатывается заново |
| Время | ISO 8601 со смещением: `2026-11-13T18:30:00+03:00` |
| Частота | До 60 запросов в минуту; сверх — `429` с `Retry-After` |
| Проверка связи | `GET /ping` → `{"status": "ok", "ip": "…"}` |
| Ошибки | `{"error": "код", "message": "текст"}`: `401` токен, `403` IP, `400` файл не читается, `404` нет заказа/задания, `409` конфликт, `429` часто, `500` — повторить через 1–5–15 мин с тем же `X-Exchange-Id` |

## 2. Потоки

| # | Что | Запрос | Когда |
| --- | --- | --- | --- |
| 1 | Номенклатура 1С → сайт | `POST /catalog` | Полная — раз в сутки; изменения — по событию или раз в час |
| 2 | Цены и остатки 1С → сайт | `POST /prices-stock` | Изменения — каждые 15–30 мин; полная — раз в сутки |
| 3 | Новые заказы сайт → 1С | `GET /orders/new` | Каждые 5 мин |
| 4 | Подтверждение заказа 1С → сайт | `POST /orders/{номер}/confirm` или `/reject` | Сразу после записи заказа в 1С |
| 5 | Статусы заказов 1С → сайт | `POST /order-statuses` | При изменении статуса |
| 6 | Документы по заказу (счёт PDF) 1С → сайт | `POST /orders/{номер}/documents` | После выставления счёта |

Файлы потоков 1–2 сайт принимает сразу (`202`, `job_id`) и обрабатывает в очереди за секунды; результат по строкам — `GET /jobs/{job_id}` (раздел 10). Номенклатура должна прийти раньше цен.

Потоки 1–2 работают на тестовом стенде. Потоки 3–6 — формат утверждён, реализация на сайте в работе.

Склад один: остаток — общий по товару. Количества могут быть дробными для товаров в метрах, килограммах и т. п. — до 3 знаков после точки (`12.5`); для штучных — целые.

## 3. Поток 1 — номенклатура

`POST /catalog?mode=delta` (только изменённые) или `mode=full` (вся номенклатура). Пробный прогон без изменений на сайте: `&dry_run=1`.

| Колонка | Обяз. | Что |
| --- | --- | --- |
| `guid` | да | GUID номенклатуры |
| `sku` | нет | Код товара на сайте. Пусто — у новой позиции кода ещё нет |
| `article` | да | Артикул производителя без бренда: `L4755-2` |
| `brand` | да* | Производитель. *Обязателен, если `sku` пуст |
| `name` | да | Наименование в 1С |
| `unit` | да | Единица: `шт`, `компл` … |
| `vat_rate` | да | `20`, `10`, `0` или `без НДС` |
| `barcode` | нет | Штрихкод |
| `group_1c` | нет | Группа в 1С (справочно) |
| `active` | да | `1` — продаётся, `0` — выведен |

```csv
guid;sku;article;brand;name;unit;vat_rate;barcode;group_1c;active
5f1c2b8a-3d4e-11ef-9a1b-0050569a1c01;LEDEME-L4755-2;L4755-2;LEDEME;Смеситель для кухни LEDEME L4755-2;шт;20;4810000000017;Смесители;1
8c4f5e1d-3d4e-11ef-9a1b-0050569a1c04;;BL 5810;TIM;Смеситель для ванны TIM BL5810;шт;20;;Смесители;1
7b3e4d0c-3d4e-11ef-9a1b-0050569a1c03;SAVOL-OLD-001;OLD-001;SAVOL;Выведенный товар;шт;20;;Аксессуары;0
```

Что сделает сайт:

- найдёт товар по `guid`; если не нашёл — по `sku`; если `sku` пуст — по «бренд + артикул» и запомнит GUID;
- не нашёл совсем — создаст новый товар (черновик для контент-менеджера) с кодом `БРЕНД-артикул` и вернёт этот код в результате задания (`created`) — **1С сохраняет его в реквизит SKU**;
- обновит наименование 1С, артикул, бренд, единицу, НДС, штрихкод, группу; описание, фото и категории сайта не трогает;
- `active = 0` — скроет товар на сайте;
- `mode=full`: если в файле нет больше 10 % товаров, которые сайт уже знает по GUID, файл не применяется (защита от обрезанной выгрузки).

Коды сайта для уже сопоставленных товаров: `GET /catalog/sku-map` → CSV `guid;sku` по всем товарам с GUID. Нужен один раз после первой загрузки, чтобы заполнить реквизит SKU в 1С.

## 4. Поток 2 — цены и остатки

`POST /prices-stock?mode=delta` или `mode=full`.

| Колонка | Обяз. | Что |
| --- | --- | --- |
| `guid` | да | GUID номенклатуры |
| `sku` | да | Код товара на сайте |
| `price` | нет | Цена без НДС, BYN: `832.26`. Пусто — «Цена уточняется» |
| `stock` | да | Свободный остаток (за вычетом резервов 1С), ≥ 0; для дробных единиц — до 3 знаков (`12.5`) |
| `stock_status` | нет | `on_order` — «под заказ», `in_stock` / `none` — снять признак |
| `updated_at` | да | Момент снятия данных в 1С |

```csv
guid;sku;price;stock;stock_status;updated_at
5f1c2b8a-3d4e-11ef-9a1b-0050569a1c01;LEDEME-L4755-2;832.26;7;in_stock;2026-11-13T18:30:00+03:00
8c4f5e1d-3d4e-11ef-9a1b-0050569a1c04;TIM-BL 5810;;0;on_order;2026-11-13T18:30:00+03:00
```

Что сделает сайт:

- найдёт товар по `guid` (или по `sku`, пока GUID не присвоен), запишет цену и остаток;
- строку старше уже применённой (`updated_at`) пропустит — повтор старого файла ничего не испортит;
- `mode=full`: у товаров, которых нет в файле, остаток станет 0 (с той же защитой 10 %);
- `mode=delta`: только строки из файла. Если 1С не умеет отбирать изменения, можно каждый раз слать полный файл в режиме `delta` — 15 000 строк обрабатываются за 1–2 секунды.

## 5. Поток 3 — новые заказы

`GET /orders/new?limit=50` — заказы, которые **менеджер сайта проверил и подтвердил**, а 1С ещё не записала; старые первыми. Пока заказ не подтверждён 1С (поток 4), он приходит в каждом ответе. Новые непроверенные заказы в выдачу не попадают.

```json
{"orders": [{
  "number": "SM-2026-000024",
  "created_at": "2026-11-13T18:42:10+03:00",
  "organization": {"guid": null, "unp": "193123457", "name": "ООО «Рога и копыта»"},
  "user": {"name": "Иван Петров", "email": "buyer@example.by", "phone": "+375290000000"},
  "delivery_address": {"title": "Склад №2", "address": "г. Минск, ул. Примерная, 1"},
  "comment": "Позвонить за час до доставки",
  "total_without_vat": 832.26, "vat": 166.45, "total": 998.71,
  "items": [{
    "product_guid": "5f1c2b8a-3d4e-11ef-9a1b-0050569a1c01",
    "sku": "LEDEME-L4755-2", "article": "L4755-2", "client_code": "WB-001",
    "name": "Смеситель для кухни LEDEME L4755-2",
    "qty": 1, "unit": "шт", "price": 832.26, "vat_rate": 20,
    "sum": 832.26, "vat": 166.45, "total": 998.71
  }]
}]}
```

Цены — без НДС на момент оформления; суммы округлены по строке. `qty` — для дробных единиц до 3 знаков. `organization.guid` — GUID контрагента 1С, если он известен сайту; иначе контрагент ищется по УНП. `client_code` — код товара у клиента (маркетплейса) или `null`.

## 6. Поток 4 — подтверждение заказа

После записи заказа в 1С:

`POST /orders/SM-2026-000024/confirm`

```json
{"guid_1c": "a9b8c7d6-…", "number_1c": "ЗК-000512", "registered_at": "2026-11-13T18:47:03+03:00"}
```

| Ответ | Когда |
| --- | --- |
| `200` | Принято (повтор с тем же `guid_1c` — тоже `200`) |
| `409 guid_conflict` | Заказ уже подтверждён с другим `guid_1c` |
| `409 order_cancelled` | Клиент отменил заказ на сайте, пока 1С его записывала — отменить документ в 1С |
| `404` | Нет такого заказа |

Если заказ записать нельзя: `POST /orders/SM-2026-000024/reject` с `{"reason": "Контрагент не найден по УНП"}` — заказ уходит менеджеру сайта на разбор.

## 7. Поток 5 — статусы заказов

`POST /order-statuses`

```json
{"statuses": [
  {"number": "SM-2026-000024", "guid_1c": "a9b8c7d6-…", "status": "shipped",
   "changed_at": "2026-11-14T10:15:00+03:00", "comment": "ТТН № 0123456"}
]}
```

| `status` | На сайте |
| --- | --- |
| `in_work` | В работе |
| `shipped` | Отгружен |
| `completed` | Выполнен |
| `cancelled` | Отменён (причина — в `comment`) |

Статусы идут только вперёд, промежуточные можно пропускать; старый `changed_at` игнорируется. Менеджер сайта тоже может менять статус вручную — статус из 1С с более поздним `changed_at` всё равно применяется. Ответ — результат по каждому заказу: `{"number": "…", "result": "ok" | "ignored" | "error", "message": "…"}`.

## 8. Поток 6 — документы по заказу

`POST /orders/SM-2026-000024/documents`, `Content-Type: multipart/form-data`:

| Поле | Что |
| --- | --- |
| `file` | PDF, до 10 МБ |
| `type` | `invoice` — счёт на оплату (позже — `waybill`, `act`) |
| `number`, `date` | Номер и дата документа в 1С |
| `guid_1c` | GUID документа в 1С — повтор с тем же GUID заменяет файл |

Ответ `200`. Документ появляется в кабинете клиента в карточке заказа.

## 9. Что нужно от разработчика 1С

1. Внешний IP сервера 1С — для белого списка.
2. Можно ли завести дополнительный реквизит номенклатуры «Код сайта (SKU)».
3. Есть ли у контрагентов GUID и можно ли выгрузить список «УНП — GUID».

## 10. Результат обработки файла

`POST /catalog` и `POST /prices-stock` отвечают `202 {"job_id": "…", "status": "queued"}`. Результат: `GET /jobs/{job_id}`.

```json
{
  "job_id": "0193f2b7-…", "type": "catalog", "status": "done",
  "rows_total": 3, "rows_ok": 2, "rows_error": 1,
  "errors": [{"line": 4, "guid": "7b3e…", "sku": "SAVOL-OLD-001", "message": "Ставка НДС «18%»: допустимо 20, 10, 0 или «без НДС»"}],
  "created": [{"line": 3, "guid": "8c4f5e1d-3d4e-11ef-9a1b-0050569a1c04", "sku": "TIM-BL 5810"}]
}
```

`status`: `queued` → `processing` → `done` (возможны ошибки отдельных строк — остальные строки применены) или `failed` (файл не применён целиком, причина в `message`). `created` — только у номенклатуры: коды сайта для новых товаров, сохранить в 1С.

## 11. Порядок запуска

1. Проверка связи: `GET /ping` с IP 1С и токеном.
2. Пробная номенклатура 100–200 строк с `dry_run=1` → разбор результата.
3. Полная номенклатура `mode=delta` → `GET /catalog/sku-map` → заполнить SKU в 1С.
4. Цены и остатки по расписанию.
5. Заказы: тестовый заказ на сайте → менеджер подтверждает → 1С забирает → подтверждает → присылает статусы и счёт.
